# V1.1.x-R · R-1-asan — arm64_lifter realloc-after-borrow UAF

**Date**: 2026-04-17 (Session #1-extra)
**Scope**: Fix heap-use-after-free in ARM64 lifter when `arm_irblock_alloc_instr` reallocates `IrBlock::instrs` mid-handler.

## Root Cause

`arm_irblock_alloc_instr` calls `realloc(blk->instrs, ...)` when capacity is exceeded. Four AArch64 handlers (LDR, STR, LDP, STP with `#offset`) acquired the main instruction pointer *before* emitting the auxiliary CONST/ADD instructions that also allocate, then wrote `ins->srcs[...]` through the now-stale pointer.

ASAN stack (pre-fix, basic_stripped.o):

```
WRITE of size 4 at 0x51d000001c90
  #0 ir_lift_arm64  src/decompiler/arm64_lifter.c:594  (LDR ins->srcs[0] stale write)
freed by
  #0 realloc
  #1 arm_irblock_alloc_instr  :70
  #2 arm_emit_const           :133
  #3 ir_lift_arm64             :583
```

## Fix

`src/decompiler/arm64_lifter.c` — cache the instruction's array index immediately after `arm_irblock_alloc_instr`, re-derive the pointer after every subsequent call that may realloc:

```c
IrInstr *ins = arm_irblock_alloc_instr(irb);
uint32_t ins_idx = irb->instr_count - 1;
...
arm_emit_const(...);          /* may realloc */
arm_irblock_alloc_instr(...); /* may realloc */
ins = &irb->instrs[ins_idx];  /* re-derive */
ins->srcs[0] = ...;
```

Applied to 4 handlers:
- LDR (line 576, write at 594)
- STR (line 616, writes at 635 and 644)
- LDP (line 672, write at 692)
- STP (line 716, writes at 736 and 745)
