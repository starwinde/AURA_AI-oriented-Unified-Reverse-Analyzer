# V1.1.x-R · R-2 — hir_emit bare-integer DEREF emits invalid C

**Date**: 2026-04-17 (Session #1-extra, post R-1-asan)
**Scope**: `test_real_binary_advanced` level-2 syntax validation — bare `*<positive_const>` deref path in `hir_emit.c`.

## Root Cause

`src/decompiler/hir_emit.c::try_emit_stack_var()` (Pattern 3, lines 374–383 pre-fix) only recognised the "already-folded" stack slot case for **negative** constants:

```c
if (val < 0 && val >= -4096) { emit var_|val| ; return 1; }
```

On AArch64 (where SP-relative spills are encoded with a **positive** unsigned offset like `[sp, #28]`) the IR sometimes reaches hir_emit as `DEREF(CONST(+28))` without the enclosing `ADD(sp, 28)` wrapper — the constant is already folded but the sign is positive. Pattern 3 returned 0, the caller at `hir_emit.c:475` fell through to the default UNOP path and emitted `*28`. gcc rejects that with:

```
error: invalid type argument of unary ‘*’ (have ‘int’)
   if (*4 >= *28) { ... }
```

## Fix (GREEN)

`src/decompiler/hir_emit.c::try_emit_stack_var()` — generalise Pattern 3 to handle both signs symmetrically:

```c
int64_t abs_off = (val < 0) ? -val : val;
if (val != 0 && abs_off <= 4096) {
    fprintf(out, "%s%" PRId64, stack_var_name_prefix(abs_off), abs_off);
    stack_var_record(abs_off);
    return 1;
}
```

The `±4096` window mirrors typical stack-frame offset magnitudes; constants outside it still fall through to the generic path (so genuine absolute-address derefs such as `*(volatile int *)0x40800000` are unaffected).

Side effect: large negative constants (< -4096) that used to return 0 now still return 0 — behaviour preserved. Zero never emits as a stack var.
