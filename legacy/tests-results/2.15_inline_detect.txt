Algorithm:
  Phase 1 — Sliding Window:
    For each position in the instruction stream, hash the mnemonic
    sequence of 8 consecutive instructions (FNV-1a). Windows appearing
    at 2+ non-overlapping locations (>= 32 bytes apart) form a group.

  Phase 2 — Function-Level:
    Detected functions (via func_detect) with <= 16 instructions get
    their full mnemonic sequence hashed. Groups with 2+ matches are
    inline candidates.

  Phase 3 — FLIRT Cross-Reference:
    All groups are checked against FLIRT match results. Known library
    function patterns are named accordingly (e.g., "memcpy (inlined)").
