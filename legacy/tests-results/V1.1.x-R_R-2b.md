# V1.1.x-R · R-2b — Call-site argument over-emission on self-ref CALL

**Date**: 2026-04-17 (Session #1-extra, follow-up to R-2a `f3aed0a`)
**Scope**: `corpus_adv_fnptr` level-2 gcc syntax FAIL — the only remaining
advanced-harness subcase after R-2a bare-integer DEREF fix. Distinct from
R-2a: this is a **call-site argument-count lowering** bug, not a deref bug.

## Reproduction (pre-fix E2E)

```
$ bash tests/decompiler/test_real_binary.sh build-rel/aura \
        build-rel/tests/decompiler/corpus/advanced.o
  [7] corpus_adv_fnptr     — decompile OK, syntax FAIL  FAIL (level 2)
Result: 19/20 PASS, 1 FAIL
```

Decompile body:

```c
int64_t func(int64_t arg0, int arg1)
{
    /* ... */
    v27 = local_8;
    func(v33, v30, v27, v3, v4, v5, v6, v7);   // 8 args vs 2-param decl
}
```

gcc (`gcc -fsyntax-only -x c -w`):

```
error: too many arguments to function 'func'
```

## Root Cause (diagnosed, file:line)

1. **`src/decompiler/arm64_lifter.c:1013-1028` (bl), `:1053-1068` (blr),
   `:1119-1132` (tail-b CALL)** — every call handler scans `rv[0..7]` and
   counts all non-UNDEF register versions as ABI args:
   ```c
   for (int ai = 0; ai < 8; ai++) {
       if (rv[ai] != IR_VAL_ID_UNDEF) n_args = ai + 1;
       else break;
   }
   ```
   Combined with the entry-block live-in seeding at `:353-358` which
   pre-assigns SSA ids 0..7 to x0..x7, every call emits `phi_count = 8`
   whenever x0..x7 stay defined until the call site — regardless of the
   real callee signature. For `corpus_adv_fnptr` the `blr x2` carries
   x0=a (reloaded), x1=b (reloaded), x2=fn (target), x3..x7=stale live-in
   seeds.

2. **`src/decompiler/hir_builder.c:341-348` (pre-fix)** — the IR→HIR
   lowering trusts `phi_count` verbatim and emits that many HIR call
   args. No trim against the callee signature exists.

3. **Name collision**: `src/core/pipeline.c:887,889` passes literal
   `"func"` to the lifter for the enclosing function, and
   `src/decompiler/hir_builder.c:337` falls back to `"func"` for
   unresolved indirect callees. The two names collide → gcc sees a
   forward-declared 2-param `func` invoked with 8 args → hard error.

## Fix (GREEN)

`src/decompiler/hir_builder.c` — add `const HirFunc *hf` to `BuildCtx`,
populate it in `hir_build()`, and at the `IR_OP_CALL` lowering trim the
emitted `arg_count` to the caller's declared `param_count` when the
resolved callee name collides with the enclosing function name:

```c
uint32_t arg_count = ins->phi_count;
if (arg_count > 0 && ctx->hf && ctx->hf->name[0] &&
    n->hir_call.func_name[0] &&
    strcmp(n->hir_call.func_name, ctx->hf->name) == 0 &&
    ctx->hf->param_count < arg_count) {
    arg_count = ctx->hf->param_count;
}
```

Least-invasive: does not touch lifter code or refactor call lowering
architecture. Only affects the self-collision case that breaks gcc;
direct calls with a resolved distinct symbol keep every arg as before.
