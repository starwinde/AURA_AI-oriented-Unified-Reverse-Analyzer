# V1.1.x-R · R-3 — func_detect merges adjacent functions in stripped relocatable objects

**Date**: 2026-04-17 (Session #fixer-r3)
**Scope**: R-3 only — dormant bug where `func_detect` on a stripped
relocatable `.o` file emits one merged function entry covering every
adjacent body instead of one entry per function.

## Reproduction (RED)

Synthetic 3-function corpus `tests/decompiler/corpus/adjacent3.c`:

```c
int f_add(int a, int b) { return a + b; }
int f_sub(int a, int b) { return a - b; }
int f_mul(int a, int b) { return a * b; }
```

Compiled `gcc -O0 -g -c` → each body is 0x20 bytes on aarch64, so
`.text` spans `[0x00, 0x60)` with three distinct FDEs. Then
`strip --strip-all` drops the symbol table *and* `.rela.eh_frame`.

At HEAD `a280ec0` (pre-fix) the new regression test
`test_func_detect_adjacent_funcs` reported:

```
Detected 1 function(s):
  [0] 0x0 – 0x60  (96 bytes)
FAIL: expected 3 functions, got 1
```

All three bodies collapsed into a single entry.

## Root Cause (diagnosed, file:line)

Two-stage failure inside the `.eh_frame` recall path:

1. **`src/parser/eh_frame_parser.c:163-164`** — `read_encoded_ptr`
   short-circuits with `if (val == 0) return 0;` *before* applying the
   `DW_EH_PE_pcrel` offset. On a stripped relocatable `.o` the FDE
   pc_begin fields carry a raw zero (the `.rela.eh_frame`
   `R_AARCH64_PREL32` entries were dropped by `strip --strip-all`), so
   the parser hands every FDE a `pc_begin = 0`.

2. **`src/symbolic/func_detect_ehframe.c:fd_ehframe_add_candidates`**
   — every FDE is added via `candidateset_add(set, 0, …)`. The dedup
   pass in `src/symbolic/candidateset.c` collapses them to a single
   candidate at `0x0`, after which `build_funclist`
   (`src/symbolic/func_detect.c:552-586`) emits one `FuncEntry`
   spanning the whole `.text`.

`pc_range` values encode as constants (not relocations), so they
survive stripping — which is what the fix leverages.

## Fix (GREEN, minimal)

`src/symbolic/func_detect_ehframe.c` — inside
`fd_ehframe_add_candidates`, when **all** FDE `pc_begin` fields are
zero, reconstruct the function starts by cumulative `pc_range` from
`text_start`. Guarded on `fi->symbol_count == 0 && fde_count >= 2` so
the path only activates on symbol-less inputs (R-3's actual target).
Symbol-rich binaries keep using the symbol table
(`CAND_CONF_SYMBOL_SIZED = 200`) as the authoritative start source,
and the original direct-add path still runs for linked binaries with
real pcrel-resolved `pc_begin` values.

Blast radius: the new branch adds 8 lines inside a single function,
does not touch `src/parser/eh_frame_parser.c`, does not touch the
`src/core/pipeline.c:824-853` band-aid, and does not change
`CandidateSet` semantics.
