# V1.1.x-R · R-5 — test_func_detect_ehframe AddrSet/CandidateSet type mismatch

**Date**: 2026-04-17 (Session #2)
**Scope**: Fix heap-buffer-overflow in `test_func_detect_ehframe` ASAN trace — test-only bug. Production code (`candidateset.c`, `func_detect_ehframe.c`) is correct.

## Root Cause

`tests/symbolic/test_func_detect_ehframe.c` allocated an `AddrSet` via a local
`test_addrset_init()` helper (backing array sized `cap * sizeof(AuraAddr)` = 64 × 8 B = 512 B)
and then passed it to `fd_ehframe_add_candidates(fi, &set, ts, te)`. The production
signature is:

```c
uint32_t fd_ehframe_add_candidates(const FileInfo *fi, CandidateSet *set,
                                    AuraAddr text_start, AuraAddr text_end);
```

`CandidateSet::items` holds `FuncCandidate` (16 B per entry with padding) but
`cs->count` and `cs->cap` overlap in memory with `AddrSet::count/cap` (both are
`uint32_t count; uint32_t cap;` trailing the pointer), so `candidateset_add()` happily
wrote entries into the 512-byte `AddrSet::addrs` buffer until it overflowed at index 32.

## Fix (test-only)

`tests/symbolic/test_func_detect_ehframe.c`:

- Removed `test_addrset_init()` / `test_addrset_free()` helpers.
- Each TC replaced `AddrSet set; test_addrset_init(&set);` with
  `CandidateSet set; candidateset_init(&set);`.
- TC-6 now reads `set.items[i].addr` instead of `set.addrs[i]`.
- All frees now go through `candidateset_free(&set)`.

Production files (`candidateset.c`, `func_detect_ehframe.c`, `func_detect_internal.h`)
were **not** modified.
