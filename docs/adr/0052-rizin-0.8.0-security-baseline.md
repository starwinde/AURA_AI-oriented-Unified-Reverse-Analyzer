# ADR-0052 — Rizin 0.8.0 shared64 + rz-ghidra 0.8.0 execution baseline

- **Status**: Accepted
- **Date**: 2026-05-06
- **Related**: ADR-0031, ADR-0032, ADR-0050, rules.md R-1/R-2/R-9/R-10

## Context

AURA 의 reference engine 은 Rizin 이지만, 디컴파일 기능은 기본 Rizin
disassembler 출력만으로는 pseudo-C 를 보장하지 않는다. Windows 환경에서
기존 0.8.2 계열 번들은 Rizin 실행 자체는 가능했으나, rz-ghidra 플러그인과
SLEIGH spec 경로가 함께 검증된 형태가 아니어서 GUI/CLI decompile 경로가
disassembly fallback 으로 내려갈 수 있었다.

2026-05-06 검증에서 다음 조합이 실제 pseudo-C 출력까지 확인되었다.

- Rizin: `0.8.0` shared64 Windows bundle
- rz-ghidra: `0.8.0`
- Rizin executable:
  `third_party/rizin/0.8.0-shared/rizin-win-installer-clang_cl-64/bin/rizin.exe`
- SLEIGH spec path:
  `third_party/rizin/0.8.0-shared/rizin-win-installer-clang_cl-64/lib/rizin/plugins/rz_ghidra_sleigh`

## Decisions

### D1 — 0.8.0 shared64 is the project execution baseline

현재 코드, 테스트, 문서의 기본 vendored Rizin 경로는
`third_party/rizin/0.8.0-shared/rizin-win-installer-clang_cl-64/...` 를
기준으로 한다. `AURA_RIZIN_BIN` 명시 override 는 계속 허용하지만, override
사용자는 해당 Rizin 에 pseudo-C backend 가 실제로 존재하는지 책임진다.

### D2 — `SLEIGHHOME` is part of the baseline

rz-ghidra `pdgj` 는 `rz_ghidra_sleigh` spec 을 필요로 한다. 따라서 CLI 와 GUI
는 `SLEIGHHOME` 이 비어 있고 vendored 0.8.0 shared64 spec 경로가 존재하면
자동으로 해당 경로를 세팅한다. 사용자가 `SLEIGHHOME` 을 명시한 경우에는
사용자 설정을 우선한다.

### D3 — 0.8.2 is not the approved decompile baseline

0.8.2 계열 자료는 과거 analyze schema 정합화 기록으로만 남길 수 있다.
신규 작업, 테스트 기준, GUI 실행 기준, 졸업작품 시연 기준에서는 0.8.0
shared64 + rz-ghidra 0.8.0 을 사용한다.

### D4 — Security warning handling is documentation, not suppression

Windows Defender, SmartScreen, 또는 엔드포인트 보안 제품이 AURA/Rizin/rz-ghidra
를 "cyber security risk" 또는 유사 항목으로 표시할 수 있다. 이 경고는
다음 특성 때문에 예상 가능하다.

- Rizin/rz-ghidra 는 바이너리 분석, disassembly, decompile 기능을 수행한다.
- AURA 는 외부 `rizin.exe` 와 plugin DLL 을 subprocess 로 실행한다.
- 사용자가 제공한 임의 바이너리를 분석하고 함수/문자열/심볼 정보를 추출한다.
- 인터넷에서 받은 zip/exe/dll 은 Windows Mark-of-the-Web 또는 평판 기반
  경고 대상이 될 수 있다.

이 경고를 코드에서 우회하거나 비활성화하지 않는다. 대신 다음 통제만
인정한다.

- 외부 도구 출처, 버전, 경로, 가능하면 해시를 문서화한다.
- 분석은 로컬에서 수행한다. `llm-context` 는 payload JSON 만 만들며 AURA
  자체가 LLM endpoint 로 자동 전송하지 않는다.
- AURA 는 악성코드 제작/은닉/실행 자동화를 제공하지 않는다.
- 보안 제품에서 격리되면 사용자는 공식 출처와 해시를 확인한 뒤 로컬 정책에
  따라 allow-list 를 적용한다.

## Consequences

- 졸업작품 시연 기준은 "Rizin 0.8.0 shared64 + rz-ghidra 0.8.0 으로 실제
  pseudo-C 가 표시되는 로컬 RE/LLM-context 도구"로 고정된다.
- 최신 Rizin 으로 올리는 작업은 별도 compatibility phase 로만 수행한다.
- 보안 경고 자체는 실패가 아니다. 다만 출처/버전/경로/네트워크 비전송 설명이
  누락되면 배포 문서 미비로 본다.
