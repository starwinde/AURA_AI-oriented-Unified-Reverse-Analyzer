# ADR-0036 — GUI v1.1 Cutter-style Workspace + Decompile Pane (Phase 11.3.1)

**Status**: Accepted
**Date**: 2026-05-03
**Deciders**: 사용자 (project owner)
**Related**: ADR-0035 (v1 project-first surface), ADR-0033 (frontend
topology), Phase 2B Rizin DECOMPILE API (`AuraRizinDecompileBody`)

---

## Context

ADR-0035 의 v1 GUI = single MainWindow + `QStackedWidget` (page 0 Project
view, page 1 함수 list TableView). 이후 사용자 검증에서 Cutter 와 같은
좌측 브라우저 + 우측 코드 뷰 구성이 필요하다는 점이 확인되었다.

- 사용자가 Ghidra/Cutter 식 multi-pane workspace 를 기대
- 함수 list 만으로는 RE 도구의 1차 가치 ("이 함수가 무엇을 하는가?")
  를 답하지 못함
- v2+ 후속 패널 (Strings / Imports / Hex / Graph / Symbols 등) 추가 시
  `QStackedWidget` 단순 모델은 매번 layout 재공사 필요

방향성 결정 (사용자 발언): **"기능은 Ghidra 처럼 확실하게, UI 는
Cutter 처럼 현대적으로"** — 기능 ambition = Ghidra-class, UI 패턴 =
Cutter-modern (dock-heavy, dark default, 클릭 응답성).

## Decision

Phase 11.3.1 = **Cutter-style dockable workspace + Decompile pane**.

### 핵심 architectural shift

ADR-0035 의 page 1 (함수 list 단일 TableView) 를 폐기하고 **nested
`QMainWindow`** 로 교체. 2026-05-06 기준 기본 구현은 단일 중앙
TableView 가 아니라 Cutter-style 좌측 브라우저 + 우측 코드 탭이다:

```
Outer QMainWindow (ADR-0035 그대로)
├── menu bar / status bar
└── QStackedWidget central
    ├── page 0 : Project view (변경 없음 — TableView + Add Binary 등)
    └── page 1 : Inner QMainWindow workspace
        ├── left upper : Functions / Xrefs tree browsers
        ├── left lower : Strings / Symbols / Imports tree browsers
        └── right      : Decompile / Disassembly / CFG / Hex tabs
```

### v1.1 표면 (확정)

| 영역 | 결정 |
|------|------|
| Workspace 구조 | nested QMainWindow, 좌측 상단 = Functions/Xrefs, 좌측 하단 = Strings/Symbols/Imports, 우측 = Decompile/Disassembly/CFG/Hex |
| Browser 표현 | Functions/Xrefs/Symbols/Imports/Strings 는 `QTreeView`. parent row 는 엔티티 대표값, child row 는 엔진 metadata. 미제공 값은 `-` 로 표시하며 GUI 가 값을 합성하지 않음. |
| Decompile backend | rz-ghidra (`pdgj`) default → 실패 시 jsdec (`pddj`) → 텍스트 (`pdd`) 자동 fallback (Cutter 동일 정책, Phase 2B caps 활용) |
| 함수 → decompile binding | **single-click row 선택** 시 dock pane 자동 갱신 (Cutter 패턴, double-click 모달 거부) |
| Decompile 캐시 | 세션 메모리 `QHash<quint64 addr, QString text>` — 같은 함수 재선택 시 재계산 없음. 영속화 = v3. |
| 첫 분석 dialog | ADR-0035 의 Analysis Options dialog (Quick/Full) 유지 — 첫 분석 시 1회. 함수 클릭은 즉시 (추가 dialog 없음). |
| Theme | Cutter-inspired dark palette (QPalette 기반, QSS 회피 = Qt-native widget 자연 통합). Light 토글 = v2. |
| Decompile pane 폰트 | `QFontDatabase::systemFont(FixedFont)` — monospace, 시스템 default. 사용자 지정 = v2. |
| Window/dock 상태 영속 | `QSettings` (Qt 표준, 플랫폼별 저장소). 마지막 project path / dock 위치 / window geometry / theme 토글 (도입 시점). |
| Multi-binary 동시 분석 | 미지원 (단일 binary, 단일 workspace). v3. |
| Dock add/remove API | DecompilePane 만 v1.1 등록. v2 패널 추가 시 동일 dock 패턴 사용 (인프라 재공사 없음). |
| gui_smoke 확장 | 기존 시나리오 + 함수 row 선택 → DecompilePane text 비어있지 않음 검증 |

## Rationale

### Cutter-style dock vs Ghidra-style 별도 window

ADR-0035 Q2 에서 이미 별도 top-level window (Ghidra) 를 거부 (close /
focus / Z-order 결정 폭증). 그 결정은 v1.1 에서도 유지. Cutter 의
`QDockWidget` 은 같은 effect (multi-pane visibility) 를 single-window
관리 하에 달성 — **Ghidra-feature × Cutter-UI** 요구사항 충족.

### Page 1 을 nested QMainWindow 로 교체 (`QStackedWidget` 유지하되 page 1 만 변경)

ADR-0035 의 outer 구조 (page 0 Project, page 1 분석) 는 보존. page 1
의 내용물만 단순 TableView → nested QMainWindow 로 교체. Outer
`QStackedWidget` 의 view 전환 / Esc Back / status bar 정책은 그대로.

대안 1 (outer QMainWindow 자체에 dock 추가) 은 거부 — Project view
도 dock 안에 들어가야 하는데, project 단위 전환과 dock 가시성이
혼선될 위험.

### Decompile backend 우선순위 = `pdgj` > `pddj` > `pdd`

Phase 2B 의 `AuraRizinDecompileBackend` enum + caps 가 이미 결정.
Cutter 도 동일 우선순위 (Cutter 의 "Ghidra Decompiler" 플러그인이
default). rz-ghidra 가 품질 ≫ jsdec, 단 일부 binary (특정 PE / 비
표준 ABI) 에서 pdgj 실패 → fallback 자동.

### Single-click 갱신 (double-click 모달 거부)

Cutter / VS Code / 모든 modern IDE 패턴. 더블클릭 = 모달 = "메뉴
열기" 시대의 흔적. 단일 클릭 = 즉시 응답 = 사용자가 "탐색 중" 임을
표현 가능.

다만 첫 분석 시 Analysis Options dialog 는 유지 (사용자가 명시적
opt-in 한 작업 — Quick/Full 선택은 의미 있는 분기).

### Decompile 캐시 = 세션 메모리

함수당 decompile dispatch = Rizin subprocess spawn 1회 (약 1-3초). 같은
함수 재선택 시 매번 spawn 하면 클릭 응답성이 무너짐. `QHash` 기반
in-memory cache 가 표준 답.

영속화 (SQLite) 거부 이유:
- 같은 binary 재open 시 hit rate 의문 (사용자가 같은 함수 다시 보는
  빈도 낮음 — 보통 한 번 보고 다른 함수로 이동)
- DB schema 추가 = 마이그레이션 + invalidation 정책 결정
- v1.1 가치 검증 후 v3 에 도입해도 늦지 않음

### Dark palette via QPalette (QSS 거부)

QSS = CSS-like 외부 stylesheet. 강력하지만 (1) 시스템 widget 의 native
look 깨뜨림, (2) Qt 버전별 호환성 이슈, (3) hover/disabled state 직접
정의 부담. QPalette = Qt-native, OS 통합 자연, hover/disabled 자동
계산. Cutter 도 QPalette 기반 dark 채택.

### QSettings 영속 (커스텀 JSON 거부)

플랫폼별 표준 저장소 (Windows registry / Linux ~/.config / macOS
plist) 자동. Qt의 표준 패턴. 커스텀 JSON = "어디 저장?" / "권한?" /
"동시 접근?" 결정 폭증.

## Consequences

### Positive

- Cutter-style modern UI = 사용자의 직접적 요구 응답.
- Dock 패턴 = v2+ 패널 추가 시 인프라 재공사 0.
- Decompile pane = "이 함수가 무엇을 하는가?" 1차 답 즉시 노출.
- Single-click 갱신 = 사용자 탐색 응답성.
- ADR-0035 의 outer 구조 보존 = 기존 ctest / CI / project-first 흐름
  영향 0.

### Negative

- Decompile dispatch 비용 (1-3초/함수, 첫 클릭) = 사용자 첫 클릭에서
  체감 지연. 캐시로 후속 클릭 즉시. (분석 취소 / progress = v2.)
- pdgj 실패 시 자동 fallback 의 "왜 텍스트가 텍스트만 (pdd)?" 사용자
  혼란 가능 — status bar 또는 pane 헤더에 backend 표기로 완화.
- gui_smoke 확장 = decompile dispatch 도 ctest 시간 증가 (~5초 → ~8초
  추정). Tier 1 양 환경 영향 점검 필요.

### Neutral

- ADR-0035 의 Analysis Options dialog 는 변경 없이 그대로 사용.
- Override editor / LLM rename = v1.1 미포함, Phase 11.3.2/.3 분리.

## Alternatives Considered

### v1.1 = ADR-0035 의 page 1 그대로 + decompile 별도 page 2 추가

거부. multi-page 가 늘어날수록 Esc/Back navigation 부담 ↑. multi-pane
이 표준 RE-tool UX.

### Multi-pane = `QSplitter` 만 (dock 없음)

거부. Splitter = 고정 레이아웃. dock = visibility / floating /
re-arrange 가능. v2+ 에서 사용자가 패널 토글하는 표준 UX 충족 못 함.

### Decompile pane = bottom dock (대신 right)

거부. 코드 view = 가로 폭 우선 (한 줄이 길음). bottom dock = 세로 폭
우선 = 코드 wrap 빈발. Cutter / Ghidra 모두 right 또는 center.

### Decompile = 새 별도 top-level window

거부. ADR-0035 Q2 의 Ghidra-style 거부 근거 그대로 (close 정책 / focus
/ Z-order 폭증).

## Implementation

Slice 단위:
- **A** — ADR-0036 + ROADMAP + CONTEXT (본 커밋)
- **B** — Page 1 nested QMainWindow scaffold + 빈 DecompilePane dock +
  dark QPalette
- **C** — `DecompilePane` 위젯 (`QPlainTextEdit` monospace) + Rizin
  DECOMPILE dispatch + backend fallback + 캐시
- **D** — 함수 row single-click → dock pane 갱신 binding
- **E** — `QSettings` window/dock geometry 영속
- **F** — gui_smoke 확장 (decompile pane 검증)
- **G** — Tier 1 양 환경 ctest 영향 점검

Phase 11.3.2 (Override editor) / 11.3.3 (LLM rename button) / 추가 dock
패널은 별도 ADR + slice 로 분리.
